# Reconstruction Workflow

The reconstruction goal was to recover longitudinal DCE-MRI information for
patients included in MAMA-MIA. MAMA-MIA provides one exam per patient, while the
original source datasets often contain multiple MRI exams/timepoints.

## Matching Strategy

The workflow links MAMA-MIA patients back to their original TCIA source data:

1. Start from MAMA-MIA `clinical_and_imaging_info.xlsx`.
2. Use `study_tcia_series_uid`/`tcia_series_uid` to identify the original source
   series.
3. Match the UID to the appropriate source dataset metadata.
4. Locate the corresponding original DICOM series and infer the anchor
   timepoint.
5. Reconstruct the remaining available timepoints for that source patient.
6. Apply view, contrast, geometry, phase-count, and visual-consistency QC.
7. Exclude quarantined patients from the active release.

## Release Builder

The release package is generated by:

```bash
./.venv/bin/python ReconstructionScripts/build_reconstructed_dataset_release.py
```

The script does not reconstruct DICOMs itself. It packages the already
reconstructed local volumes into a clean release description.

Main responsibilities:

- scan active reconstructed volume folders under `Reconstructed_Datasets`;
- detect patient, exam/timepoint, and DCE phase files;
- normalize reconstructed IDs, including ISPY2 hyphen/underscore differences;
- read MAMA-MIA clinical/imaging metadata;
- detect QC-quarantined patients and remove them from the active release;
- merge patient-level QC summaries when available;
- write patient, exam, and phase manifests;
- write active, full-status, and nonreleased clinical/imaging tables;
- write an Excel workbook version for manual review;
- write a machine-readable `release_summary.json`;
- write local release documentation.

Generated local release folder:

```text
DatasetRelease/reconstructed_mamamia_longitudinal/
|-- README.md
|-- prepare_hf_upload.py
`-- metadata/
    |-- clinical_and_imaging_info_active_reconstructed.csv
    |-- clinical_and_imaging_info_with_reconstruction_status.csv
    |-- clinical_and_imaging_info_nonreleased.csv
    |-- patient_manifest.csv
    |-- exam_manifest.csv
    |-- phase_manifest.csv
    |-- quarantine_manifest.csv
    |-- release_summary.json
    `-- data_dictionary.csv
```

## Hugging Face Upload Preparation

The Hugging Face staging folder is produced by:

```bash
./.venv/bin/python DatasetRelease/reconstructed_mamamia_longitudinal/prepare_hf_upload.py
```

The staging script:

- writes the public dataset card;
- writes public metadata files;
- removes internal release/quarantine columns from public metadata;
- stages NIfTI files using hardlinks by default, so the local disk does not
  duplicate the full dataset;
- excludes quarantine folders and audit-only internal tables.

The current public dataset is available at:

https://huggingface.co/datasets/hfigueiras/LMBM
